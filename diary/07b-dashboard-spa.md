## What I changed outside apps/dashboard

- **`packages/core/src/http/server.ts` — one line, a real bug.** `@fastify/cors@11` defaults
  `methods` to `'GET,HEAD,POST'`, so a browser preflight for PATCH or DELETE is answered with an
  allow-methods header that omits them and the real request is never sent. Every browser client
  hits this: `apps/admin` cannot flip a tenant to passive without it. Now passes an explicit
  method list. Symptom to recognise: an `OPTIONS` 204 in the store log with **no** PATCH line
  after it.
- `apps/dashboard/package.json` added `@mercatus/ui` and the frontend catalog entries, so
  `pnpm-lock.yaml` and `pnpm-workspace.yaml` moved (pnpm added two `minimumReleaseAgeExclude`
  lines by itself).
- `diary/screenshots/07b-*.jpg`, this file, `lessons/07b-dashboard-spa.md`,
  `docs/decisions-made-overnight.md`.

## What works, verified by running it

- Sign in as `acme`/`owner` through `/dev/login/staff`, land on `/products`.
- Product list, add, edit, remove — all four round-trip through the real store API and RLS.
- Orders list and order detail, against an order placed through the public checkout.
- Settings: name, slug, branding, licence status/state.
- The passive banner: `insert into licence_state (tenant_id, status) ... 'passive'` and the banner
  appears within the 10s poll, with the whole dashboard still usable (CG3 — screenshot).
- `turbo run typecheck lint` clean for `@mercatus/dashboard` and `@mercatus/core`;
  `vite build` produces `dist/` (442 kB js, 136 kB gzipped).

## What does not work yet

- **The dashboard is not in `aspire/AppHostA/apphost.cs`.** I was scoped to `apps/dashboard` and
  the AppHost is shared with two other agents' apps. Whoever wires the front ends in needs:
  `AddViteApp("dashboard", "../../apps/dashboard", ...)` with `VITE_STORE_API_URL` pointing at the
  store and `PORT=5173` (`vite.config.ts` reads `PORT`, falling back to 5173, `strictPort: true`).
- No tests. There is no test script in `apps/dashboard/package.json`, so `turbo run test` skips it.
- `PATCH /api/settings` does not exist on the store (deliberate — `tenants` has no RLS policy), so
  the settings page reads and never writes. The edit belongs in the platform console.
- Auth is the stub. `src/auth/adapter.ts` is the one file the Identity phase replaces.
- The licence banner polls `/api/licence` every 10s; there is no SSE and does not need one.
